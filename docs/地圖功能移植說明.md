# 地圖顯示規格書

此文件定義「景點清單頁」與「地圖頁」之間的顯示規格，目標是讓不同網站的景點資料在視覺呈現、欄位內容與互動行為上保持一致。

本文件不包含 RAG、文本抽取或後端推薦邏輯。系統已假設另一個頁面會提供完整的景點清單資料，地圖頁只負責把資料一致地渲染出來。

## 1. 目標與範圍

### 1.1 目標

- 讓來源頁提供的景點清單，可以在地圖頁中以一致格式呈現。
- 讓景點卡片、地圖 marker、資訊窗與路線顯示使用同一份資料。
- 讓這組 UI 可以被移植到另一個網站，且不用依賴原本的推薦流程。

### 1.2 範圍

規格涵蓋以下內容：

- 景點卡片要顯示哪些欄位。
- 地圖 marker 如何對應景點。
- 點擊卡片或 marker 時要發生什麼事。
- 路線如何從景點清單生成。
- 沒有完整資料時的 fallback 顯示方式。

不在範圍內的內容：

- 景點來源資料怎麼產生。
- 推薦分數怎麼算。
- RAG、AI 推論或向量檢索流程。

## 2. 核心顯示模型

地圖頁使用同一份景點資料，同時驅動三個視圖：

1. 左側景點卡清單。
2. 右側 Google Maps marker 與資訊窗。
3. 行程路線或導航連結。

每個景點至少需要一筆標準化資料，才能同時被卡片與地圖使用。

## 3. 景點資料規格

### 3.1 必要欄位

每個景點物件至少要提供：

- `name`：景點名稱。
- `position`：`{ lat, lng }` 座標。
- `area`：地區或城市名稱。
- `rating`：評分字串或數字。
- `reason`：顯示在卡片與資訊窗的推薦說明。
- `tags`：一組可選標籤。
- `reviewsCount`：評論數。
- `source`：資料來源描述，可選。
- `dataInsufficient`：是否需要資料不足提示，可選。

### 3.2 建議欄位

如果來源頁已有更完整的資料，建議額外提供：

- `id`：穩定不變的識別碼。
- `category`：例如景點、美食、購物。
- `image`：卡片縮圖。
- `duration`：建議停留時間。
- `estimatedCost`：預估費用。
- `xai`：分析摘要與輔助分數區塊。

### 3.3 名稱規範

為了讓卡片、marker 和路線選取同步，景點名稱必須一致且可比對。

- 同一景點在清單與地圖中應使用相同 `name`。
- 若來源資料有別名，應先正規化成單一名稱。
- 當名稱不可避免有差異時，需在資料前處理階段做 mapping。

## 4. 景點卡片規格

景點卡片是主要的內容閱讀入口，需固定顯示下列資訊：

- 景點名稱。
- 地區或城市。
- 評分。
- 推薦原因或摘要。
- 類別或標籤。
- 縮圖。
- AI 分析區塊，如果來源頁有提供。

### 4.1 卡片互動

- 點擊卡片時，該景點應成為目前焦點。
- 焦點景點在清單、地圖 marker 與資訊窗之間應同步。
- 若卡片支援加入行程，按鈕行為應與地圖的路線資料一致。

### 4.2 卡片狀態

- 選取中的卡片應有明顯高亮。
- 資料不足時需顯示提示，但不應阻斷卡片渲染。
- 內容過長時應保持截斷與展開一致的策略。

## 5. 地圖顯示規格

### 5.1 Marker 規則

每個景點都應對應一個 marker。

- marker 位置使用景點 `position`。
- marker 標題使用景點 `name`。
- 點擊 marker 後應打開資訊窗。
- marker 點擊後，清單焦點應同步切換到同一景點。

### 5.2 資訊窗內容

marker 的資訊窗至少要顯示：

- 景點名稱。
- 評分。
- 推薦原因。
- 評論數，或資料不足提示。
- 來源摘要或來源標記。

資訊窗內容應與卡片的語氣和欄位保持一致，不要在兩邊出現不同版本文案。

### 5.3 視角控制

- 選取某景點時，地圖應平移到該景點。
- 地圖應適度放大，讓使用者能清楚看見附近 marker。
- 如果沒有任何景點，地圖區塊應顯示空狀態或提示訊息。

## 6. 路線顯示規格

### 6.1 路線生成條件

- 當行程中有至少 2 個景點時，地圖可以顯示路線。
- 少於 2 個景點時，不顯示路線，只顯示 marker。

### 6.2 路線呈現方式

- 優先使用地圖內建路線功能。
- 若地圖 SDK 不支援路線，或路線 API 被拒絕，應提供外部導航連結作為 fallback。
- 路線應以景點座標或明確地點名稱為準，避免因名稱模糊造成錯誤導航。

### 6.3 路線資料一致性

行程順序必須與來源頁一致，除非產品明確要求可排序。

## 7. 資料一致性規則

這部分是移植時最重要的約束。

### 7.1 顯示內容一致

同一景點在不同頁面上應維持一致的：

- 名稱。
- 地區名稱。
- 評分格式。
- 描述語氣。
- 標籤集合。

### 7.2 視覺一致

- 景點卡片的資訊密度應固定。
- marker 顏色、選取狀態與高亮樣式應一致。
- 空狀態、載入中與錯誤狀態應使用同一組文案風格。

### 7.3 資料不足處理

如果來源頁缺少座標或部分內容，地圖頁仍應能顯示：

- 名稱。
- 基本描述。
- 資料不足提示。

若沒有座標，可採用預設座標、暫存座標或提示需補資料，但不建議讓 UI 整體失敗。

## 8. 互動流程

### 8.1 基本流程

1. 來源頁提供景點清單。
2. 地圖頁載入相同資料。
3. 使用者點擊卡片或 marker。
4. 地圖聚焦到該景點。
5. 資訊窗顯示對應內容。
6. 若使用者加入行程，路線區塊同步更新。

### 8.2 狀態同步

- 目前焦點景點只應有一個。
- 卡片選取狀態、marker 選取狀態與資訊窗內容應同步。
- 切換分組或篩選條件時，焦點應更新到可見景點範圍內的第一筆或保留目前選取狀態。

## 9. 空狀態與錯誤狀態

### 9.1 空狀態

當沒有景點資料時，地圖頁應顯示簡潔空狀態，例如：

- 尚無景點資料。
- 請先在上一頁選擇或匯入景點清單。

### 9.2 錯誤狀態

當地圖 API 無法載入時，應顯示明確錯誤訊息，而不是空白畫面。

### 9.3 資料異常

- 缺少座標時，不應讓整頁崩潰。
- 缺少評分或評論數時，可顯示 `-` 或預設字樣。
- 缺少圖片時，可用統一預設圖。

## 10. 技術建議

以下做法適合移植到新網站：

- 以單一景點資料結構驅動卡片、地圖與路線。
- 將名稱正規化、別名 mapping 與座標 mapping 放在資料前處理層。
- 地圖元件只負責渲染，不負責推導景點資訊。
- 若要保留 Google Maps，建議使用動態載入，避免首頁成本過高。

## 11. 移植清單

若要把這組顯示規格搬到其他網站，至少要完成以下項目：

1. 定義統一的景點資料 schema。
2. 確保來源頁與地圖頁使用同一份欄位名稱。
3. 建立名稱與座標的對應層。
4. 實作卡片、marker、資訊窗與路線的同步狀態。
5. 補齊空狀態、資料不足與錯誤狀態。

## 12. 驗收標準

若符合以下條件，即可視為規格達成：

- 來源頁與地圖頁看到的是同一批景點。
- 同一景點在卡片、marker 與資訊窗的名稱與描述一致。
- 點擊任一入口都能同步到同一個焦點景點。
- 至少 2 個景點時可生成路線。
- 缺少部分資料時仍可正常顯示，不會讓整頁失效。
